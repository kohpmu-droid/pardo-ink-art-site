אתר בית (עמוד נחיתה) לקליניקת הבוטיק **Pardo Ink Art** — קעקועים אמנותיים, איפור קבוע, קעקועים רפואיים, הסרת לייזר והדרכות.

## מבנה

- `IMG_2402.jpg` — הלוגו המוצג כרגע

## פרסום אוטומטי של מאמרים

`tools/publish_from_queue.py` מפרסם מאמר אחד מהתור (`content/meta` + `content/bodies`)
ומוסיף לו כרטיסייה ב-`articles.html`.

**התזמון אקראי.** ה-workflow (`.github/workflows/publish-article.yml`) מתעורר כל שעתיים,
והסקריפט מחליט אם עברו מספיק שעות — מרווח אקראי בין 12 ל-24 שנבחר מחדש אחרי כל פרסום
ונשמר ב-`content/.publish_state.json`. אם קובץ המצב חסר או פגום — מפרסם, כדי שהתור
לא ייתקע בשקט.

**מונה המאמרים** בכותרת כל קטגוריה נספר מחדש בכל ריצה (`refresh_counts`) ולא מוגדל,
כך שריצה שנכשלה מתוקנת בריצה הבאה. עד 19.8.2026 המונה היה תקוע על 12/14 במקום 19/21
כי ה-regex הקודם חיפש אותו במקום הלא נכון ונכשל בשקט.

**להרצה ידנית:** Actions ← Publish queued article ← Run workflow.

### שלושה שלבים

התיקייה בדרייב היא תיבת דואר נכנס: מה שיושב בה עדיין לא פורסם.

**1. פרסום (ענן, `sync-gallery.yml`)** — כל יום ראשון ב-06:00, וגם ידנית:
Actions ← Sync gallery images from Drive ← Run workflow. `tools/sync_gallery_images.py`:

1. סורק את שלוש התיקיות ומדלג על כל מה שכבר פורסם
2. מוריד, מיישר לפי EXIF, מקטין ל-1400px ודוחס ל-JPEG (‏~70–100KB במקום 8MB)
3. שומר כ-`gNN/pNN/lNN.jpg` וממקם את החדשות **בראש** הגלריה
4. שם הקובץ בדרייב הופך ל-alt של התמונה — לכן כדאי שמות תיאוריים בעברית

הוא **לא דוחף ל-main**. הוא פותח Pull Request מהענף `gallery-sync`, כדי שאפשר יהיה
לראות את התמונות לפני שהן עולות לאוויר ולמחוק מהענף מה שלא מתאים לגלריה (פליירים,
מודעות, צילומי תעודות). ריצה נוספת לפני מיזוג מעדכנת את אותה בקשה.

**2. ניקוי הדרייב (ענן, `archive-gallery.yml`)** — מופעל אוטומטית כשה-PR מוזג ל-main.
`tools/archive_drive_images.py` מעביר כל תמונה שכבר יושבת בריפו לתת-תיקייה **פורסם**
בתוך תיקיית הקטגוריה. התיקייה הראשית נשארת בדיוק רשימת מה שממתין.

**3. גיבוי למחשב ומחיקה (מקומי, מתי שנוח)**

```
python tools/archive_to_disk.py            # מוריד, מוודא ומפנה
python tools/archive_to_disk.py --dry-run  # רק מראה מה היה קורה
```

מוריד את הקבצים מ"פורסם" בגודל המלא אל `F:\תוכן\תמונות לאתר\<קטגוריה>`
(ניתן לשינוי ב-`GALLERY_ARCHIVE_DIR`), ורק אחרי שהקובץ נשמר שלם שולח את העותק
שבדרייב לפח — הפיך 30 יום. קובץ שכבר קיים על הדיסק מזוהה לפי גודל ו-md5 גם אם שמו
שונה, כך שהוא לא יורד פעמיים.

**רץ אוטומטית**: משימה ב-Windows Task Scheduler בשם `PARDO - gallery backup to F`
מריצה `tools/archive_task.py` כל יום ב-20:00 דרך `pythonw.exe` — בלי חלון, והפלט
נכתב ל-`%LOCALAPPDATA%\pardo-gallery-archive.log`. המשימה מוגדרת `StartWhenAvailable`,
כך שאם המחשב היה כבוי בשעה הזו היא רצה בהזדמנות הראשונה שהוא נדלק, וגם
`RunOnlyIfNetworkAvailable` כדי לא להיכשל בלי אינטרנט.

השלב הזה הוא היחיד שדורש שהמחשב יהיה דלוק. אם הוא לא נדלק — התמונות פשוט
ממתינות ב"פורסם", והפרסום לאתר לא נפגע.

לבדוק מתי רצה לאחרונה:

```powershell
Get-ScheduledTaskInfo -TaskName "PARDO - gallery backup to F"
```

לבטל את התזמון: `Unregister-ScheduledTask -TaskName "PARDO - gallery backup to F"`

### מעקב ומצב

`images/.gallery_state.json` — מפתח לפי מזהה הקובץ ב-Drive, לכן שינוי שם בדרייב לא
יגרום להעלאה כפולה, ומחיקה מהדרייב לא מוחקת מהאתר. לכל רשומה `archived` שאומרת אם
היא כבר פונתה מהתיקייה הראשית.

כדי להסיר תמונה מהאתר צריך למחוק אותה מ-`images/` וגם מרשימת התמונות בעמוד.

**קבצים שיושבים ישירות ב"תמונות לאתר" ולא בתת-תיקייה — מתעלמים מהם.**

### רשימת התמונות בעמוד

בכל עמוד גלריה יש בלוק שהסקריפט מנהל:

```js
/* AUTO-GALLERY-START */
var images = [ ["p25", "פירסינג טבור"], ["p24", ""] ];
/* AUTO-GALLERY-END */
```

הסדר בתוך המערך הוא סדר התצוגה — אפשר לערוך ידנית (למשל להעלות תמונה מוצלחת לראש),
הסקריפט שומר על מה שכתוב שם ורק מוסיף בהתחלה. `alt` ריק נופל חזרה לטקסט ברירת המחדל
של העמוד.

### הרשאות גוגל

היקף ההרשאה הוא `drive` מלא — קריאה, העברה בין תיקיות ושליחה לפח — דרך אותו OAuth
client של פרויקט ה-Google Cloud שמשמש את `GBP_*` ב-`pardo-auto-publisher`.
שלושה סודות ב-GitHub: `GDRIVE_CLIENT_ID`, `GDRIVE_CLIENT_SECRET`, `GDRIVE_REFRESH_TOKEN`.
להרצה מקומית — אותם שמות במשתני סביבה או בקובץ `.env` בשורש הריפו (לא נכנס לגיט).

להפקת טוקן: `python tools/gdrive_auth.py <CLIENT_ID> <CLIENT_SECRET>`.
דורש ש-`http://localhost:8080/` יהיה redirect URI מאושר אצל אותו client, ושה-scope
של דרייב יאושר במסך ההסכמה. אם ה-app במצב Testing — הטוקן פג אחרי 7 ימים, ואז צריך
להעביר אותו ל-Production (או להפיק מחדש כל שבוע).

**פתיחת ה-PR** דורשת שההגדרה Settings ← Actions ← General ←
"Allow GitHub Actions to create and approve pull requests" תהיה דלוקה. אם היא כבויה,
הענף עדיין נדחף וה-workflow מדפיס קישור לפתיחה ידנית.
